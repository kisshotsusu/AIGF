# 02 任务排序系统

> 把"要做什么"变成"按顺序、按资源约束、可靠地做完"。**本系统的最高约束（见 00 规则 #0）：任务排序由大模型语义规划驱动，禁止硬编码任务类型/流程。**

---

## 1. 核心原则：模型驱动，而非硬编码

- **意图、任务类型、参数、步骤、工具选择、结果解释、是否完成、下一步**全部由大模型决定。本地代码只校验模型输出是否为合法字段与工具参数。
- **禁止**：关键词/正则分类器、固定站点流程、组合式业务工具（如"搜索并播放"）、本地成功硬门槛（如"窗口标题必须变化"）。
- 工具层只执行原子操作、记录时间、返回结构化事实；最终完成由**独立核验模型**结合最新证据判断。

---

## 2. 语义规划器（认知层，MiMo `mimo-v2.5`）

每条用户消息先经语义规划器产出结构化计划（字段经本地类型校验，布尔/整数不得用字符串冒充）：

```yaml
Plan:
  is_task:            bool          # 是否要求取得结果/检查/查找/修改/执行
  actionable:        bool          # 是否必须调用工具（与 is_task 分开）
  response_mode:     enum          # answer|execute|clarify
  execution_strategy:enum          # direct_answer|tool_loop|vision_loop|web_loop|code_loop
  preferred_tools:   [string]
  required_capabilities: [string]
  steps:             [string]
  success_criteria:  string
  final_action_requires_verification: bool
  risk_level:        enum          # 供本地权限层判断
  needs_clarification: bool
  clarification_question: string|null
  visual_required:   bool          # 是否必须读屏（视觉路由唯一依据，不看关键词）
  interaction_mode:  enum          # none|observe|solve|game
  implementation_change: bool       # 是否持久改程序实现/UI/路由/输出
  code_scope:        enum          # self|external|new_project|none
```

规划器不可用时 → 不执行外部动作的保守回退；**不通过关键词猜测任务**。

## 3. 真实调度机制（已实现）

### 3.1 直播语音优先队列（单消费者）
```
B站事件 → LiveAssistant.handle_event → 过滤/去重/冷却/分类
  ├─ 弹幕 → LLMClient → 截短回复
  ├─ 送礼 → 模板回复
  └─ 进场 → 去重欢迎语（最高语音优先级）
→ speech PriorityQueue（单消费者）→ TTSClient（单 GPU 合成锁 + 指数退避重试 4 次）
→ Windows 顺序播放 → 仅语音成功才写 welcomed 冷却
```

### 3.2 HomeAgent 工具循环预算（家庭/自动化）
- `max_tool_rounds = 28`：**失败轮次预算**——成功读取/搜索/检查/写入不消耗；工具失败、状态不确定、伪工具调用、证据不足、未验证结束才累计一次。
- `max_tool_iterations = 112`：独立总迭代资源上限，防无失败但无进展的死循环。
- 每轮 assistant `tool_calls` 后 tool 消息连续（避免 DeepSeek "insufficient tool messages" 400）；单工具异常转失败 tool 消息继续循环。
- **独立完成检查**：MiMo 消费本地工具证据核验，默认重试 2 次；接口异常 `fail_closed` 不得报告完成。

### 3.3 提醒/闹钟（TaskStore）
- `Task/<task-id>.json` 是唯一持久化位置；创建/列出/确认/推进周期/成功后删除一次性任务均由 `TaskStore` 完成，与聊天进度、自升级恢复完全独立。

### 3.4 自升级恢复（仅 self）
- `HomeAgent/state/task-recovery.json` 仅记录 `is_self_upgrade=true` 且 `status=running` 的任务；普通/定时任务不写。旧版本遗留非升级 `running` 启动时清除。

### 3.5 屏幕关怀（低优先级后台）
- Qt 每 `interval_seconds`（默认 300）触发后台任务：截主屏 → MiMo 生成隐私安全关怀语 → 删除截图；用户任务执行中或上一轮未结束时跳过，不排队不抢占。

## 4. 并发与资源约束（真实）

- **Vision 网页/GUI 工具**固定在单一专用线程（`max_workers=1`）共享浏览器会话，避免并发抢占。
- **ChatWorker** 单消费者串行消费 FIFO；任务/最终 TTS 播放期间新输入仍可提交并立即显示，但只有当前 worker 真正结束后才启动下一项。
- **单实例锁**：所有常驻服务 `InstanceLock`（见 00 规则 #4.5）。

---

## 5. 状态机与预算（设计契约）

```
created → queued → ready ⇄ running
                        ├─ blocked（依赖/资源未满足）
                        ├─ done
                        └─ failed → retry<max → queued | retry≥max → cancelled
```
- 工具循环失败轮次预算 28、总迭代 112（见 3.2）。
- 超时即失败：释放资源 → 触发重试/失败。

## 6. 设计演进：显式优先级 / 依赖 / 资源锁（★ 仍由模型指派）

当存在**并发多任务**时，可在计划层引入显式优先级（非本地硬编码类型）：
- P0 紧急/安全（用户直接命令、确认弹窗回应）
- P1 高（直播实时响应）
- P2 普通（主动互动、记忆巩固）
- P3 低（清理/统计）
- P4 后台（模型预热、批量导入）

依赖 DAG（`depends_on`）、资源锁（`mouse`/`screen`/`mic` 单任务独占）作为**执行层资源调度**补充，但**优先级与任务分类必须由模型在计划中给出**，本地不得用关键词推导。

## 7. 模块结构（设计目标）

```
TaskOrchestrator
├── SemanticPlanner   # MiMo 计划（真实已实现于 HomeAgent.agent）
├── SpeechQueue      # 直播语音优先队列（真实已实现）
├── ToolLoop         # 工具循环 + 失败预算 + 完成核验（真实已实现）
├── ReminderStore    # TaskStore 提醒/闹钟（真实已实现）
├── Recovery         # task-recovery 自升级（真实已实现）
├── Scheduler        # ★ 并发多任务优先级/依赖/资源锁（设计演进）
└── Monitor          # 超时/重试/失败告警
```

## 8. 接口契约（设计目标）

```python
class TaskOrchestrator(Module):
    def plan(self, message) -> Plan            # 语义规划（真实：HomeAgent.agent）
    def submit(self, task) -> str               # 入队（含模型指派的 priority）
    def cancel(self, id) -> bool
    def pause/resume(self) -> None
    def get_status(self) -> dict
    def on_complete(self, id, cb) -> None
    def list(self, state=None) -> list
```

## 9. 本系统特有规则

1. **禁止硬编码任务类型/流程**（最高优先级，见 00 #0）。
2. **模型判完成**：最终完成由独立核验模型基于最新证据判断，本地不得用窗口标题/固定按钮/关键词作硬门槛。
3. **不虚构成功**：仅验证终态后汇报；`fail_closed` 时不得报告完成。
4. **不可抢占保护**：执行中键鼠序列、文件写操作标记 `non_preemptable`。
5. **依赖闭环检测**：`depends_on` 成环直接拒绝。
6. **可观测**：全程 `trace_id`，审计日志可回溯"为何此时执行"。

## 11. 与其他系统关系

- **← 03 感知**：事件（如"有人进房"）经语音队列转欢迎任务（P1）。
- **← 01 记忆**：记忆中的"约定/待办"转 `Task/*.json` 定时任务。
- **→ 04 执行**：计划 `steps`/`preferred_tools` 由执行层落地。
- **→ 认知层**：工具结果回填记忆（成功/失败经验）。
- **依赖 05**：预算、规划器参数、调度策略来自配置。
