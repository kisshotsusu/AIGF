# 01 记忆分级关联性系统

> 记忆是 Agent 的"大脑"。本系统解决两件事：**分级存储**（按重要度/时效分层，控制成本与召回质量）与**关联性检索**（用图谱 + 向量把零散记忆连成网络）。本文件整合真实实现（AI Read 04），并在其之上标注「设计演进」目标。

---

## 1. 目标与定位

- 持久化重要互动、用户画像、偏好、知识与规则，支撑角色一致性。
- 在推理时快速召回"相关"记忆，而非全量扫描。
- 与现有 `workspace/memory/*.jsonl`、`LongTermMemory/memory.db`、`state/live-context.json` 兼容。

---

## 2. 真实实现：三类记忆生命周期（AI Read 04）

> 真实系统已有三层**不同生命周期**的记忆，互不互为备份：

| 级别 | 名称 | 真实存储介质 | 生命周期 | 写入约束 |
|------|------|--------------|----------|----------|
| L0 | 工作/上下文记忆 | 进程内 deque / 短期历史 / 语义规划上下文（最近 8 条） | 单次会话 / TTL | 直播短期上下文 `state/live-context.json` 默认清理 >120 分钟 |
| L1 | 短期记忆 | `workspace/memory/YYYY-MM-DD.jsonl`（每日共享记忆） | 按日，角色管理器可编辑标签/隐私/附件 | 普通互动落盘；闲聊也记流水 |
| L2 | 长期记忆 | `LongTermMemory/memory.db`（SQLite） | 长期，按重要性保留 | **只存高价值**：身体/情绪/重大事件/偏好/习惯/关系/约定；`importance≥70`、标签 3–5、摘要 ≤20 字、关键原句；普通闲聊不存 |
| L3 | 知识固化 | `workspace/*.md`（IDENTITY/CHARACTER/SOUL/RULES/HOME_RULES/LIVE_RULES/ABILITIES） | 几乎不变 | 由版本/人工维护，不自动写入 |

**附加任务态（非记忆，但同属持久化）**：
- `HomeAgent/state/task-recovery.json`：仅记录**未完成自身代码升级**（`is_self_upgrade=true` 且 `status=running`）；普通/定时任务不写。
- `Task/<task-id>.json`：提醒/闹钟/周期任务的唯一持久化位置；一次性任务成功后删除。

### L2 长期记忆记录字段（真实 schema）
```yaml
LongTermMemory:
  id:          uuid
  created_at:  datetime
  user_id:     string        # 规范用户 ID（如 owner）
  scene:       enum          # live|home|...
  category:    enum          # 身体/情绪/事件/偏好/习惯/关系/约定
  tags:        [string]      # 3–5 个
  summary:     string        # ≤20 字
  detail:      string        # 关键原句
  importance:  0..100         # ≥70 才写入
  privacy:     enum           # public|private|secret
  source:      string
```
> 写入原则：**是否值得保存、类别和摘要均由记忆模型判断**；已移除 `always_keywords`/`ignore_keywords` 等本地语义分类兜底（见 AI Read 06）。

## 3. 设计演进：关联性图谱 + 向量召回（★ 待实现）

在真实三层之上，本架构的设计目标是增加**关联性**与**语义召回**：

### 3.1 关联边 Edge（图谱）
```yaml
Edge:
  from: uuid
  to:   uuid
  kind: enum   # tag|entity|temporal|semantic|causal
  weight: 0..1
```
由共现/共引/实体共指自动建边；每节点边数量设上限（≤50）防爆炸。

### 3.2 分级流转（巩固 / Consolidation）
```
L0(会话中) --会话结束或重要性达阈值--> L1(日文件)
L1 --访问频次高 / importance≥阈值 / 跨会话相关--> L2(长期)
L2 中不常访问且低 importance --> 遗忘曲线衰减/归档
L3 由人工/版本管理维护，不自动写入
```

### 3.3 检索 `retrieve` 混合策略（演进目标）
1. 标签/实体过滤 → 2. 向量相似（语义召回 top-k）→ 3. 图谱扩散（沿高 weight 边 1~2 跳）→ 4. 按 `importance × recency × access_count` 重排。

## 6. 本系统特有规则

1. **隐私隔离**：直播短期上下文与家庭上下文彼此分层；私密/家庭附件/私人照片仅家庭模式可读；`secret` 不进入公开召回。不同直播用户名默认是独立观众，不互相套用记忆。
2. **模型判存**：是否值得保存、类别、摘要均由记忆模型判断，禁止本地关键词兜底。
3. **重要性透明**：`importance` 由可解释因子计算，不在黑盒里调。
4. **不重复记忆**：写入前去重（同 content+同实体视为更新）。
5. **图谱轻量**：边数量每节点 ≤50。
6. **可解释召回**：返回每条命中附带"为何召回"（标签/向量相似度/图谱路径）。
7. **清理不删根**：`clear_live_context` 只原子写 `state/live-context.json=[]`，不删 `logs/messages.jsonl`、每日记忆或 SQLite 长期记忆。

## 8. 与其他系统关系

- **← 03 感知**：视觉/音频识别的结构化结果作为 `event`/`fact` 写入。
- **← 交互**：用户消息、弹幕、指令作为 `interaction` 节点。
- **→ 认知层**：`retrieve` 提供推理上下文；支撑角色一致性。
- **→ 02 任务**：记忆中的"约定/待办"转化为 `Task/*.json` 定时任务。
- **依赖 05**：重要性阈值、保留天数、演进的向量后端来自配置。
