# 00 设计规则与总原则

> 本文件定义**所有子系统必须遵守**的通用规则、接口契约与安全边界，是整合「绿地设计（00–07）」与「真实实现（AI Read）」的最高约束。
> 各子系统文档中的"本系统特有规则"在冲突时让位于本文件。

---

## 0. 最高优先级开发规则（来自真实系统 AI Read）

1. **禁止任务类型与任务流程硬编码。** 大模型负责理解用户意图、生成计划、选择工具、解释工具结果并决定下一步；工具只执行原子操作并返回结构化事实。**禁止**关键词/正则分类器、固定站点流程、组合式业务工具和本地成功硬门槛。本地代码仅校验模型输出的字段与工具参数，不得用原始用户文本重新分类、补写搜索词、拆分动作、覆盖模型计划或把某句话强制路由到某个业务执行器。
2. **工具原子性契约。** 工具只做"一个可验证动作"（观察/点击/输入/启动/停止/读取/写入），返回真实结果与证据；不生成面向用户的任务结论，不决定业务是否完成，不指定固定后续流程。最终完成由独立核验模型结合最新证据判断。
3. **不虚构成功（fail-closed）。** 只有验证最终 URL/状态或媒体实际播放后才能汇报完成；接口异常时默认判定失败，不得把候选回复或旧截图当作成功证明。
4. **信息优先级**：`当前代码与 YAML` > `AI Read` > 根 `README.md` > 各模块历史说明。完成代码任务前必须同步对应 `AI Read 01–08` 章节（影响当前能力写入 `06`）。

---

## 1. 分层与解耦规则

1. **单向数据流**：输入适配 → 感知 → 记忆 → 认知/规划 → 执行 → 输出。除"执行反馈回流记忆"外，禁止下层反向调用上层业务逻辑。
2. **接口隔离**：模块只通过 `initialize / process / get_status / shutdown` 四个标准生命周期方法 + 各自公开 API 与外界通信；**禁止直接读写其他模块内部状态**。
3. **配置单一权威**：所有可调参数由 `05 设置接口` 定义；其他模块只读配置，不在代码里硬编码路径、密钥、模型名。**唯一写入权威是 `CharacterService`（角色工作台）**，经它双向同步 `HomeAgent/config.yaml` 与 `config.d/*`。
4. **可替换性**：识别模型、LLM、TTS、输入后端均须支持热插拔——更换实现不应改动调用方代码。

---

## 2. 统一接口契约（生命周期）

```python
class Module:
    def initialize(self, config: dict) -> None:   # 读 05 配置，分配资源
    def process(self, payload: Any) -> Any:        # 主处理逻辑
    def get_status(self) -> dict:                  # 返回健康/指标/队列长度
    def shutdown(self) -> None:                    # 释放资源、flush 记忆/日志
```

- 初始化失败必须抛出带原因的错误，禁止"静默降级"到不可用状态。
- `shutdown` 必须幂等（可重复调用），且保证记忆/日志落盘。

---

## 3. 数据契约规则

1. **时间戳**：一律 ISO-8601（含时区），如 `2026-09-01T12:45:00+08:00`。
2. **ID**：记忆记录用 `id`；任务/会话用 UUIDv4，禁止用自增整数当跨系统主键。
3. **事件对象**：跨系统传递统一用 `Event`：`{id, type, source, time, payload, trace_id}`，`trace_id` 用于全链路追踪。
4. **错误对象**：`{code, message, module, recoverable, detail}`，禁止吞掉异常后返回空结果。
5. **工具返回契约**：所有工具统一返回 `ok/status`、`observation/result`、`error`、`tool_submitted_at`、`tool_completed_at`、`tool_elapsed_ms`、`tool_sequence`；视觉结果另带截图采集/分析时间。模型只能采用同一对象的最新有效证据，过期结果应淘汰。

---

## 4. 异步与并发规则

1. **感知与执行异步**：03 感知层产出事件后非阻塞投递，不等待认知层处理。
2. **认知层串行化推理**：LLM 调用受并发上限约束（由 05 配置），避免 token/配额风暴。
3. **资源锁**：
   - 同一物理资源（如鼠标、屏幕、麦克风）同一时刻只被一个任务持有；04 模拟输入系统维护全局资源锁。
   - Vision 网页/GUI 工具固定在单一专用线程（`max_workers=1`）内执行，共享同一浏览器会话，避免并发抢占。
4. **超时与重试**：任何外部调用（LLM/网络流/系统命令）必须有 `timeout` 与 `retry` 策略（来自 05 配置），默认不无限阻塞。
5. **单实例锁（InstanceLock）**：HomeAgent、角色管理器、直播控制台、直播助手、Sound MCP、Vision MCP 均使用跨进程文件锁，第二实例在初始化/占端口/加载模型前退出。禁止以"端口暂未打开"作为唯一单实例依据（Vision 预加载期间尚未监听端口）。

## 5. 安全边界规则（最高优先级）

1. **权限分级**（映射真实 `computer_control` 配置）：
   - `read`：只读感知（看屏幕、听声音）——默认开放。
   - `ui`：模拟键鼠、窗口操作——需会话级授权（如 `computer_control` 授权）。
   - `system`：执行 shell、安装、删除、联网请求——需**显式确认 + 二次确认 + 审计日志**。
2. **不可逆操作拦截**：删除文件/卸载/格式化/发消息等动作进入 `system` 级必须弹出确认，并记录到审计日志。
3. **隐私分级**：记忆与感知结果带 `privacy` 标签（`public`/`private`/`secret`）；`secret`/私密记忆仅在家庭/授权模式可读。**直播短期上下文与家庭上下文彼此隔离**——家庭系统提示不读取原始直播流水。
4. **密钥不落盘明文**：API Key 只存 `.env`，配置以 `${ENV:VAR}` 引用；常见变量 `DEEPSEEK_API_KEY`/`MIMO_API_KEY`/`CUSTOM_API_KEY`/`IMAGE_API_KEY`/`DASHSCOPE_API_KEY`/`XAI_API_KEY`/`STT_API_KEY`/`BILIBILI_COOKIE`。
5. **能力边界**：不冒充用户作出付款、交易、合同等现实承诺（沿用 RULES.md 第 4 条）。
6. **不伪造**：不伪造工具结果、文件、图片、联网信息或电脑操作（沿用 RULES.md 第 7 条）。
7. **登录态网页保护**：不得为登录任务启动临时浏览器或关闭用户现有浏览器；优先复用现有浏览器 DOM。

---

## 6. 可追溯与可观测规则

1. **全链路 trace_id**：一次用户请求或外部事件触发的整条处理链共享同一 `trace_id`。
2. **结构化日志**：每条日志含 `time, level, module, trace_id, message`；敏感字段脱敏。
3. **审计日志**：所有 `system` 级动作写入独立审计日志（谁、何时、做了什么、结果）。
4. **指标**：各模块 `get_status` 暴露队列长度、成功率、延迟、资源占用。

---

## 7. 失败隔离与降级规则

1. **单点不崩全局**：任一模块崩溃被 supervisor 捕获，标记 `degraded`，其余模块继续运行。Vision/Sound/GPT-SoVITS 是独立本地服务，单服务失败返回可诊断错误而非让 UI 假死。
2. **降级路径**：
   - LLM 不可用 → 走本地规则/缓存回复（沿用 ABILITIES 的"短期回复兜底"）。
   - 规划器不可用 → 不执行外部动作的保守回退，不通过关键词猜测任务。
   - 视觉模型不可用 → 退化为纯 DOM/无感知；GUI 视觉后端（`preload_model:false`）按需懒加载。
   - 音频识别不可用 → 退化为纯文本交互。
   - TTS 不可用 → 降级系统 SAPI/Windows 语音。
   - 模拟输入不可用 → Agent 转为"建议模式"只给指令不执行。
3. **熔断**：某依赖连续失败超阈值，自动熔断并告警，避免雪崩。

---

## 8. 命名、目录与配置写入规则

1. 子系统文档编号固定 `0x_名称.md`；配置文件统一放 `config/`。
2. **配置原子写 + 未知字段保留**：设置保存采用原子临时文件替换，UI/服务必须保留未知字段；`config.yaml` ↔ `config.d/*.yaml` 由 `CharacterService` 按修改时间双向同步，改配置应走角色工作台或两处一并修改。
3. 保留现有约定以降低迁移成本：
   - 记忆落盘沿用 `workspace/memory/YYYY-MM-DD.jsonl` + 字段 `id/time/type/user/privacy/tags/content/category/importance/source`，以及 `LongTermMemory/memory.db` 结构化长期记忆。
   - LLM 接口沿用 OpenAI 兼容协议（base_url / model / api_key / temperature / top_p），主模型 MiMo `mimo-v2.5`。
   - 音频输出沿用本地 TTS HTTP 服务（GPT-SoVITS `:9879`，CosyVoice2 `:50000` 暂屏蔽）。
4. 外部输入源类型枚举：`network_video` / `desktop` / `webcam` / `microphone` / `system_audio` / `network_audio`。
